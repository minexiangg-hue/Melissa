# Melissa 0.3.0 — A local voice

Released 2026-10-26. Preview: **https://hermoscare.com/melissa**.

The Listen control can now prepare English speech locally with Kokoro v1.0, the `af_heart` voice and CPU-only inference. Playback is requested explicitly and uses Melissa's authenticated API. The existing device voice remains an explicit fallback when local synthesis fails.

## Behavior and boundaries

A separate loopback worker keeps model inference outside the teaching process. It accepts one synthesis at a time, validates pinned model assets at startup, bounds input and output, and terminates inference on timeout or caller disconnect. Text and audio are processed in memory; the worker does not save request content or access logs.

The application accepts passages only from the guest's saved lessons or Melissa's replies. Its durable speech ledger has separate daily limits and does not change learning progress or consume teaching allowances. Deletion removes speech ownership and cancels active work. Schema migration 3 adds this ledger while preserving the existing learner records.

The shared browser player supports cancellation during preparation and playback, long passages in bounded chunks, explicit retries, mobile autoplay recovery, and cleanup on navigation, expiry or deletion. Preferences identify the voice as AI-generated. Audio is prepared as a complete WAV for each chunk; this release does not provide streaming speech, microphone recording, transcription, or pronunciation assessment.

## Verification

- 126 application tests passed; five opt-in live AI checks remain skipped.
- Nine model-free Python worker tests passed, including busy rejection, hard timeout, disconnect cancellation and recovery.
- 48 desktop/mobile browser cases passed across root and `/melissa` deployments, including explicit device fallback and session recovery.
- Strict TypeScript, ESLint, formatting and production builds passed.
- A real model and production browser check received a 307,148-byte WAV, verified actual playback, stopped playback, and deleted the temporary guest. The mobile view had no tested accessibility violations or browser errors.

On this server with two CPU inference threads, the 76-character benchmark took 2.260 seconds for 4.829 seconds of audio; a 275-character reply took 8.112 seconds for 17.343 seconds of audio. The loaded inference process used approximately 449 MiB RSS. These are execution and latency measurements, not a listening-quality evaluation. See [worker setup and benchmarks](../speech-worker.md) and [audio architecture](../audio.md) for configuration, dependency licenses and current limits.

The deployment keeps the worker on private port 3210 and serves audio through the existing HTTPS application. The live HTTPS browser check prepared a 306,668-byte WAV in 3.255 seconds and confirmed playback, Stop, accessibility and deletion. Both application and speech services are enabled and healthy; the existing host site still returns HTTP 200. Learner data and the previous environment/build were backed up before migration and restart, and the SQLite backup passed its integrity check.
